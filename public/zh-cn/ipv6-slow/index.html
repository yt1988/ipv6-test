IPv6 本身比 IPv4 慢吗？

不慢。IPv6 的包头大一点，但差别小到测不出来。真正拉开差距的是线路：运营商的 IPv6 可能链路更少、更绕，和其他网络的 IPv6 互联更少，或者干脆走隧道。所以有的网络 IPv6 更快（不用 NAT，设备更新），有的明显更慢。上面的对比会告诉你是哪一种。

IPv6 为什么会慢、会卡？

常见原因，按出现多少排列：

  • 线路绕路：很多运营商的 IPv6 出国或连到其他网络时，经过的交换点比 IPv4 少，延迟多出几十毫秒。在国内访问境外网站，IPv6 经常绕路。
  • MTU 有问题：满尺寸的 IPv6 数据包在某段链路（PPPoE 拨号、隧道）上丢了，小请求正常，大网页卡住。上面的大数据包测试查的就是这个。
  • 隧道：6to4 和 Teredo 的 IPv6 要绕到很远的中继服务器。
  • 路由器或光猫：固件太旧；IPv6 防火墙把回包丢了；或者路由器自己的上联没有 IPv6，却给设备分了 IPv6 地址。
  • 代理或 VPN 只接管 IPv4，IPv6 的流量直接出去了。

IPv6 慢怎么解决？

先换个时间再测：只有晚上慢，是运营商那边拥堵。大数据包测试没通过的话，在路由器的 WAN 或 IPv6 设置里调低 MTU（PPPoE 拨号可以试 1480 或 1452）。升级固件，重启路由器和光猫。如果 IPv6 一直慢很多，把上面的数字发给运营商，这是他们线路的问题。在那之前也不用太担心：IPv6 连得慢时，浏览器会自动改用 IPv4（Happy Eyeballs），大部分网站照常能用。

要不要关掉 IPv6？

一般不要。关掉以后，只有 IPv6 的网站、部分应用和游戏会用不了，微软也不支持关闭 IPv6 的 Windows。如果你的 IPv6 确实更差，可以改成 IPv4 优先，IPv6 留给需要它的服务：Windows 把注册表值 DisabledComponents 设为 0x20（微软官方的「IPv4 优先于 IPv6」）；Linux 在 /etc/gai.conf 里取消「precedence ::ffff:0:0/96 100」这一行的注释。

帮助

这个测试检测什么？

看你的网络能不能用 IPv6，会不会因为 IPv6 拖慢上网。浏览器会像打开普通网站一样，访问几个很小的测试地址：

只有 IPv4 和只有 IPv6 的网站：两种网络各自通不通，用的是哪个地址。

双栈网站（IPv4 和 IPv6 地址都有）：浏览器选哪个，会不会先傻等 IPv6 超时再改用 IPv4。

IPv6 大数据包：在新连接上发一个够大的请求，必须用满尺寸的数据包。线路的 MTU 有问题时，小请求正常、大请求有去无回，表现就是网页一直转圈。

不带域名的 IP 地址（一个 IPv6、一个 IPv4）：不靠 DNS 能不能连 IPv6，以及你是不是在只有 IPv6、靠 NAT64 打开 IPv4 网站的网络上。

每项测试同时问两到四家服务（Cloudflare、Google、DNSPod、AliDNS、icanhazip、ipify），用最先响应的那家，所以一家被墙或变慢不会让测试失败。

分数怎么算？

满分 10 分，参考 test-ipv6.com 的思路，衡量你的网络对 IPv6 准备得怎么样：能打开只有 IPv6 的网站 4 分，IPv6 大数据包不丢 2 分，双栈网站打开不用等 2 分，不靠 DNS 也能连 IPv6 1 分，浏览器优先走 IPv6 1 分。IPv6 第一次响应超过 3 秒扣 1 分。

完全没有 IPv6 是 0 分，但这不代表网络坏了：所有网站照样能通过 IPv4 打开。10 分表示 IPv6 处处能用，而且不拖慢上网。

没有 IPv6，怎么开通？

现在多数运营商都提供 IPv6，常常只是没打开。进路由器的管理页面，找到 IPv6（或 WAN → IPv6）设置，选运营商用的方式，一般是 DHCPv6 或「原生」，并打开前缀委派（PD）。再确认局域网这边会给设备分配 IPv6 地址（SLAAC 或 DHCPv6）。

如果是光猫拨号，IPv6 可能要在光猫里打开，或者把光猫改成桥接、由路由器拨号。路由器没有 IPv6 选项，或者运营商没开通，就打客服问。手机流量一般都有 IPv6，哪怕家里 Wi-Fi 没有。

不开通也不影响上网：所有网站照常走 IPv4，只是用不了只有 IPv6 的网站和应用。

IPv6 地址能连，只有 IPv6 的网站却打不开？

说明 IPv6 线路本身没问题，是 DNS 没有返回 IPv6 地址（也叫 AAAA 记录），浏览器根本不知道这个网站有 IPv6 地址。常见原因：路由器开了「过滤 AAAA 记录」或「IPv6 DNS 过滤」（不少国内路由器默认就开着），DNS 服务器把 AAAA 记录丢了，或者代理软件自己接管了 DNS。

解决办法：在路由器里关掉 AAAA 过滤，或者换成公共 DNS，比如 223.5.5.5、119.29.29.29。

大数据包测试（MTU）是什么？

网络上的数据是一个个包传的，每个包最大约 1500 字节（这个上限叫 MTU）。有些 IPv6 线路（隧道、PPPoE 拨号、没配好的路由器）上，满尺寸的包过不去某一段，而提醒对方「发小一点」的消息又被拦了。结果是小请求正常、看起来能上网，但大网页、图片、下载一直卡着。

测试在新连接上向一个只有 IPv6 的站点发 3.5 KB 的请求，来回都要用满尺寸的包。如果小的 IPv6 测试通过、这项没通过，可以在路由器的 IPv6 或 WAN 设置里调低 MTU（PPPoE 拨号可以试 1480 或 1452），或者联系运营商。

IPv6 能用，浏览器为什么选了 IPv4？

这不算故障，只有 IPv6 的网站照样能打开。浏览器会同时试两种地址，谁先连上用谁（这个机制叫 Happy Eyeballs）。IPv4 胜出，说明在你的网络上 IPv6 建立连接更慢，或者系统优先用 IPv4：Windows 对隧道 IPv6（6to4、Teredo）就是这样，很多代理和 VPN 软件也只转发 IPv4。

开着代理或 VPN，测的是谁？

基本是代理的。开着代理时，测试站点是经过代理访问的，显示的地址和 IPv6 支持情况都是代理服务器的；代理只转发 IPv4 的话，看起来就像你没有 IPv6。想测自己的网络，先关掉代理（或者让这些测试地址直连），再重新测试。

只有 IPv6、靠 NAT64 打开 IPv4 网站的网络是什么？

是一种正常的网络部署方式，几乎所有应用都能用，不用管。有些移动网络只给手机分配 IPv6。为了还能打开只有 IPv4 的网站，运营商的 DNS 会给这些网站编一个 IPv6 地址（DNS64），再由网关转成 IPv4（NAT64）。用域名能正常打开网站，但直接输入 IPv4 地址就连不上，测试就是靠这一点认出来的。

会收集我的数据吗？

本站收不到你的测试结果。大部分测试请求从你的浏览器直接发到各个测试站点（Cloudflare、Google 等），它们和你打开的任何网站一样，能看到你的 IP 地址。

路径 MTU 和「IPv6 不应答时浏览器等多久」连的是 1ms.dog 自己在东京的服务器（v4.ipv6.1ms.dog、v6.ipv6.1ms.dog、he.ipv6.1ms.dog）。它能看到你的 IP 地址、连接的包大小（MSS）和连接发起的时间；某个协议连不上时，页面还会把测出的那个地址发给它，问它看到了什么。这些只在内存里留一分钟，用来回答这个页面，不写日志，也不存盘。

只有你点分享时，结果才会放进链接里：链接只含各项结果和耗时，国家只在你勾选时才带上，不含 IP 地址。代码在 GitHub 上开源，服务器的代码也在里面。

IPv4 和 IPv6 对比测的是什么？

四家网络（Cloudflare、Google、Akamai、DNSPod）各有一个只走 IPv4 和一个只走 IPv6 的入口。测试同时请求两边，在已经建好的连接上测延迟（取三次里最小的），所以差值反映的是运营商给两种协议的线路，跟服务器无关。结论取两种协议都有响应的网络的差值中位数，相差 10 ms（或 15%）以内算一样快。

它不影响得分：IPv6 慢一点也照样能用。Google 在中国大陆没有响应；DNSPod 的服务器在中国大陆，从境外测两边都会很慢，它的差值反映的是到中国的线路。
