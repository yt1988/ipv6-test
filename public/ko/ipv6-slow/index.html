IPv6가 IPv4보다 원래 느린가요?

아니요. IPv6 헤더가 조금 크긴 하지만, 측정할 수 없을 만큼 작은 차이예요. 차이를 만드는 건 경로예요. 통신사의 IPv6는 회선이 적거나 멀리 돌아가고, 다른 네트워크와 IPv6로 연결된 곳이 적거나, 터널을 거치기도 해요. 그래서 IPv6가 더 빠른 곳(NAT가 없고 장비가 새로움)도 있고 확실히 느린 곳도 있어요. 어느 쪽인지는 위의 비교에서 볼 수 있어요.

IPv6가 느리고 끊기는 이유는?

자주 있는 원인부터 순서대로:

  • 돌아가는 경로: 많은 통신사가 IPv6로 해외나 다른 네트워크에 나갈 때 IPv4보다 적은 연동 지점을 거쳐서, 수십 밀리초가 더 걸려요. 중국 본토에서 해외로 가는 IPv6는 자주 돌아가요.
  • MTU 문제: 최대 크기 IPv6 패킷이 어떤 구간(PPPoE, 터널)에서 사라져서, 작은 요청은 되는데 큰 페이지는 멈춰요. 위의 큰 패킷 테스트가 이걸 확인해요.
  • 터널: 6to4와 Teredo의 IPv6는 멀리 있는 중계 서버를 거쳐요.
  • 공유기나 모뎀: 오래된 펌웨어, 응답을 버리는 IPv6 방화벽, 자기 회선에는 IPv6가 없는데 기기에 IPv6 주소를 나눠 주는 공유기.
  • IPv4만 처리하는 프록시나 VPN을 쓰는데, IPv6 트래픽만 그대로 나가는 경우.

느린 IPv6는 어떻게 고치나요?

먼저 시간대를 바꿔 다시 재 보세요. 저녁에만 느리면 통신사 쪽 혼잡이에요. 큰 패킷 테스트가 실패하면 공유기의 WAN 또는 IPv6 설정에서 MTU를 낮추세요(PPPoE라면 1480이나 1452). 펌웨어를 업데이트하고 공유기와 모뎀을 재부팅하세요. 그래도 IPv6가 늘 훨씬 느리면 위의 수치를 통신사에 보내세요. 경로는 통신사가 고쳐야 해요. 그동안에도 크게 걱정할 필요는 없어요. IPv6 연결이 느리면 브라우저가 알아서 IPv4로 바꾸니까(Happy Eyeballs) 대부분의 사이트는 잘 열려요.

IPv6를 꺼야 할까요?

보통은 끄지 않는 게 좋아요. 끄면 IPv6 전용 사이트와 일부 앱·게임을 쓸 수 없고, Microsoft도 IPv6를 끈 Windows는 지원하지 않아요. IPv6가 정말 더 나쁘다면 IPv4를 우선으로 바꾸고, IPv6는 필요한 서비스를 위해 남겨 두세요. Windows에서는 레지스트리 값 DisabledComponents를 0x20으로 설정하고(Microsoft의 'IPv6보다 IPv4 우선'), Linux에서는 /etc/gai.conf의 'precedence ::ffff:0:0/96 100' 줄의 주석을 해제하세요.

도움말

이 테스트는 무엇을 확인하나요?

내 인터넷에서 IPv6를 쓸 수 있는지, IPv6 때문에 느려지지 않는지 확인해요. 브라우저가 일반 사이트를 열 때처럼 작은 테스트 주소 몇 개에 접속해요.

IPv4 전용과 IPv6 전용 사이트: 각각 연결되는지, 어떤 주소로 연결되는지.

듀얼 스택 사이트(IPv4와 IPv6 주소가 모두 있음): 브라우저가 어느 쪽을 고르는지, IPv6 시간 초과를 기다렸다가 IPv4로 바꾸지는 않는지.

IPv6 큰 패킷: 새 연결에서 최대 크기 패킷이 필요한 크기의 요청을 보내요. 경로의 MTU에 문제가 있으면 작은 요청은 되는데 큰 요청은 사라져서, 페이지가 계속 로딩 중으로 보여요.

도메인 이름 없는 IP 주소(IPv6 하나, IPv4 하나): DNS 없이 IPv6로 연결되는지, NAT64를 쓰는 IPv6 전용 네트워크인지.

각 테스트는 2~4곳(Cloudflare, Google, DNSPod, AliDNS, icanhazip, ipify)에 동시에 물어보고 가장 먼저 온 응답을 써요. 한 곳이 막히거나 느려도 테스트가 실패하지 않아요.

점수는 어떻게 계산하나요?

10점 만점이고, 네트워크가 IPv6에 얼마나 준비되어 있는지를 보는 test-ipv6.com의 방식을 따랐어요. IPv6 전용 사이트가 열리면 4점, IPv6 큰 패킷이 통과하면 2점, 듀얼 스택 사이트가 기다림 없이 열리면 2점, DNS 없이 IPv6로 연결되면 1점, 브라우저가 IPv6를 고르면 1점이에요. IPv6 첫 응답이 3초를 넘으면 1점을 빼요.

IPv6가 전혀 없으면 0점이지만, 인터넷이 고장 났다는 뜻은 아니에요. 모든 사이트가 IPv4로 잘 열려요. 10점은 IPv6가 어디서나 되고 아무것도 느리게 만들지 않는다는 뜻이에요.

IPv6가 없어요. 어떻게 쓸 수 있나요?

통신사와 요금제에 따라 IPv6를 제공하기도 하고 아직 안 하기도 해요. 제공하더라도 공유기에서 꺼져 있는 경우가 많아요. 공유기 관리 페이지에서 IPv6(또는 WAN → IPv6) 설정을 찾아 통신사 방식(보통 DHCPv6 또는 자동)으로 켜고, 내부 네트워크에 IPv6 주소를 나눠 주는 설정(SLAAC 또는 DHCPv6)도 켜세요.

공유기에 설정이 없거나 통신사가 지원하지 않으면 고객센터에 문의하세요. 휴대폰 모바일 데이터는 Wi-Fi에 없더라도 IPv6가 있는 경우가 많아요.

IPv6가 없어도 인터넷은 문제없어요. 모든 사이트가 IPv4로 열리고, IPv6 전용 사이트와 앱만 쓸 수 없어요.

IPv6 주소로는 연결되는데 IPv6 전용 사이트가 안 열려요. 왜죠?

IPv6 연결 자체는 문제없어요. DNS가 IPv6 주소(AAAA 레코드)를 돌려주지 않아서, 브라우저가 그 사이트에 IPv6 주소가 있다는 걸 모르는 거예요. 흔한 원인은 공유기의 AAAA 필터 설정, AAAA 레코드를 버리는 DNS 서버, DNS를 직접 처리하는 프록시 앱이에요.

해결 방법: 공유기의 AAAA 필터를 끄거나, 1.1.1.1이나 8.8.8.8 같은 공용 DNS로 바꾸세요.

큰 패킷 테스트(MTU)가 뭔가요?

데이터는 최대 약 1,500바이트 크기의 패킷으로 나뉘어 전달돼요(이 상한을 MTU라고 해요). 일부 IPv6 경로(터널, PPPoE, 설정이 잘못된 공유기)에서는 최대 크기 패킷이 어떤 구간을 지나지 못하고, '더 작게 보내 달라'는 알림도 막혀요. 작은 요청은 되니 연결은 멀쩡해 보이지만, 큰 페이지나 이미지, 다운로드가 멈춘 채로 있어요.

테스트는 새 연결에서 IPv6 전용 호스트에 3.5KB 요청을 보내서, 오가는 양쪽 모두 최대 크기 패킷을 쓰게 해요. 작은 IPv6 테스트는 통과하는데 이것만 실패하면, 공유기의 IPv6 또는 WAN 설정에서 MTU를 낮추거나(PPPoE라면 1,480이나 1,452) 통신사에 문의하세요.

IPv6가 되는데 브라우저는 왜 IPv4를 고르나요?

고장이 아니고, IPv6 전용 사이트도 잘 열려요. 브라우저는 두 주소를 동시에 시도해서 먼저 연결되는 쪽을 써요(Happy Eyeballs라는 방식이에요). IPv4가 이겼다면 내 네트워크에서 IPv6 연결이 더 느리거나, 시스템이 IPv4를 우선하는 거예요. Windows는 터널 IPv6(6to4, Teredo)에서 그렇게 하고, IPv4만 전달하는 프록시나 VPN 앱도 많아요.

프록시나 VPN을 쓰고 있어요. 누구의 결과인가요?

대부분 프록시의 결과예요. 프록시를 켜면 테스트 사이트에 프록시를 거쳐 접속하니, 보이는 주소와 IPv6 지원 여부는 프록시 서버의 것이에요. IPv4만 전달하는 프록시라면 IPv6가 없는 것처럼 보여요. 내 네트워크를 테스트하려면 프록시를 끄거나(또는 이 호스트들은 직접 연결하게 하고) 다시 테스트하세요.

NAT64를 쓰는 IPv6 전용 네트워크란?

흔히 쓰는 정상적인 구성이고 거의 모든 앱이 잘 되니 따로 할 일은 없어요. 일부 모바일 네트워크는 휴대폰에 IPv6만 할당해요. 그래도 IPv4 전용 사이트에 접속할 수 있도록, 통신사 DNS가 그 사이트용 IPv6 주소를 만들어 주고(DNS64) 게이트웨이가 IPv4로 바꿔 줘요(NAT64). 도메인 이름으로는 사이트가 열리지만 IPv4 주소를 직접 입력하면 연결되지 않아요. 테스트는 이 차이로 알아내요.

제 데이터를 수집하나요?

이 사이트는 테스트 결과를 받지 않아요. 테스트는 브라우저에서 각 테스트 호스트(Cloudflare, Google 등)로 바로 가고, 다른 사이트와 마찬가지로 그 호스트들은 IP 주소를 볼 수 있어요. 결과가 링크에 담기는 건 직접 공유할 때뿐이에요. 링크에는 각 테스트 결과와 시간만 들어가고, 국가는 체크했을 때만, IP 주소는 들어가지 않아요. 코드는 GitHub에 공개되어 있어요.

IPv4와 IPv6 비교는 무엇을 보여 주나요?

네 네트워크(Cloudflare, Google, Akamai, DNSPod)에는 각각 IPv4 전용 입구와 IPv6 전용 입구가 있어요. 테스트는 양쪽에 동시에 접속하고 연결된 상태에서 지연 시간을 재요(세 번 중 가장 낮은 값). 그래서 차이는 서버가 아니라 통신사가 두 방식에 마련한 경로의 차이를 보여 줘요. 결론은 양쪽 모두 응답한 네트워크들의 차이 중앙값이고, 10 ms(또는 15%) 이내면 같은 속도로 봐요.

점수에는 영향이 없어요. 조금 느려도 IPv6는 쓸 수 있어요. Google은 중국 본토에서 응답하지 않아요. DNSPod 서버는 중국 본토에 있어서 다른 지역에서는 양쪽 모두 느리고, 그 차이는 중국까지의 경로를 보여 줘요.
