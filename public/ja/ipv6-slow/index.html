IPv6 は IPv4 より遅いの？

IPv6 そのものは遅くありません。ヘッダーが少し大きいだけで、測れるほどの差は出ません。違うのは経路です。プロバイダーの IPv6 は回線が少ない・遠い、他のネットワークとの IPv6 接続が少ない、あるいはトンネル経由のことがあります。そのため IPv6 のほうが速い回線（NAT がなく、新しい設備）もあれば、はっきり遅い回線もあります。上の比較でどちらかがわかります。

IPv6 が遅い・重いのはなぜ？

よくある原因を多い順に：

  • 遠回りの経路：多くのプロバイダーでは、IPv6 で海外や他のネットワークへ出るときの接続点が IPv4 より少なく、数十ミリ秒増えます。中国本土から海外への IPv6 はよく遠回りします。
  • MTU の問題：フルサイズの IPv6 パケットがどこかの区間（PPPoE、トンネル）で失われ、小さなリクエストは通るのに大きなページが止まります。上の大きなパケットのテストで確認できます。
  • トンネル：6to4 や Teredo の IPv6 は遠くの中継を通ります。
  • ルーター：古いファームウェア、応答を落とす IPv6 ファイアウォール、自分の回線に IPv6 がないのに IPv6 アドレスを配るルーター。
  • IPv4 しか扱わないプロキシや VPN で、IPv6 は直接出ている。

遅い IPv6 を直すには？

時間帯を変えてもう一度測ってください。夜だけ遅いならプロバイダー側の混雑です。大きなパケットのテストが失敗するなら、ルーターの WAN または IPv6 設定で MTU を下げます（PPPoE なら 1480 か 1452）。ルーターやモデムを更新して再起動します。IPv6 がいつも大幅に遅いなら、上の数値をプロバイダーに伝えてください。経路を直せるのは彼らです。その間も、IPv6 の接続が遅ければブラウザは自動で IPv4 に切り替えるので（Happy Eyeballs）、ほとんどのサイトは使えます。

IPv6 は無効にすべき？

普通は不要です。無効にすると IPv6 専用のサイトや一部のアプリ・ゲームが使えなくなり、Microsoft も IPv6 を無効にした Windows をサポートしていません。IPv6 が本当に悪いなら、IPv4 を優先にして IPv6 は必要なもののために残しましょう。Windows ではレジストリ値 DisabledComponents を 0x20 に（Microsoft の「IPv6 より IPv4 を優先」）、Linux では /etc/gai.conf の「precedence ::ffff:0:0/96 100」のコメントを外します。

ヘルプ

このテストは何を調べますか？

ブラウザは普通のサイトを開くのと同じように、小さなテスト用アドレスをいくつか開きます。

IPv4 専用と IPv6 専用のサイト：それぞれのインターネットにつながるか、どのアドレスからか。

デュアルスタックのサイト（両方を持つ）：ブラウザがどちらを選ぶか、IPv6 を待ってから諦めていないか。

IPv6 の大きなパケット：新しい接続で、最大サイズのパケットが必要な大きさのリクエストを送ります。経路の MTU が壊れていると、小さなリクエストは通るのに大きなものは消え、ページが読み込み中のまま止まります。

名前のないアドレス（IPv6 と IPv4 を一つずつ）：DNS なしで IPv6 が使えるか、NAT64 を使う IPv6 専用ネットワークかどうか。

各テストは 2〜4 社（Cloudflare、Google、DNSPod、AliDNS、icanhazip、ipify）に同時に問い合わせ、最初の応答を採用します。1 社がブロックされたり遅かったりしても失敗にはなりません。

スコアはどう計算しますか？

10 点満点で、ネットワークの IPv6 への準備度を測る test-ipv6.com の考え方にならっています。IPv6 専用サイトにつながれば 4 点、IPv6 で大きなパケットが通れば 2 点、デュアルスタックのサイトが待たずに開けば 2 点、DNS なしで IPv6 が使えれば 1 点、ブラウザが IPv6 を選べば 1 点。IPv6 の最初の応答に 3 秒以上かかると 1 点減点。IPv6 がまったくなければ 0 点ですが、サイトはすべて IPv4 で普通に使えます。

10 点は、IPv6 がどこでも使え、何も遅くしないという意味です。

IPv6 がありません。どうすれば使えますか？

日本の光回線では、IPv6（IPoE）はプロバイダーへの申し込みで使えることが多く、対応ルーターも必要です。ルーターの管理画面で IPv6（IPv6 IPoE、IPv4 over IPv6 など）の設定を確認し、LAN 側で IPv6 アドレスを配る設定（SLAAC や DHCPv6）が有効か見てください。

ルーターに設定がない、またはプロバイダーが未対応なら問い合わせてください。スマートフォンのモバイル回線は、Wi-Fi になくても IPv6 があることが多いです。

IPv6 がなくても困ることはほぼありません。サイトはすべて IPv4 で使え、IPv6 専用のサイトやアプリが使えないだけです。

IPv6 は通るのに IPv6 専用サイトが開けないのはなぜ？

IPv6 接続自体は問題なく、DNS が IPv6 アドレス（AAAA レコード）を返していないため、ブラウザはサイトに IPv6 アドレスがあることを知りません。よくある原因：ルーターの AAAA フィルター設定、AAAA レコードを落とす DNS サーバー、DNS を自分で処理するプロキシ。

ルーターの AAAA フィルターを切るか、1.1.1.1 や 8.8.8.8 などのパブリック DNS を設定してください。

大きなパケットのテスト（MTU）とは？

データは最大約 1,500 バイトのパケットで送られます。一部の IPv6 経路（トンネル、PPPoE、設定ミスのルーター）では、最大サイズのパケットが途中の回線を通れず、「小さくして送って」という通知もブロックされます。小さなリクエストは通るので接続は正常に見えますが、大きなページや画像、ダウンロードが止まったままになります。

テストは新しい接続で IPv6 専用ホストに 3.5 KB のリクエストを送り、双方向で最大サイズのパケットを使います。小さな IPv6 テストが通ってこれが失敗するなら、ルーターの IPv6 や WAN の設定で MTU を下げる（PPPoE なら 1,480 や 1,452 を試す）か、プロバイダーに相談してください。

IPv6 が使えるのに、なぜブラウザは IPv4 を選ぶの？

ブラウザは両方を試し、先につながった方を使います（Happy Eyeballs）。IPv4 が勝つのは、あなたのネットワークで IPv6 の接続が遅いか、システムが IPv4 を優先しているからです。Windows はトンネル経由の IPv6（6to4、Teredo）でそうしますし、IPv4 しか通さないプロキシや VPN アプリも多くあります。故障ではなく、IPv6 専用サイトは開けます。

プロキシや VPN を使っています。誰の結果ですか？

ほぼプロキシの結果です。プロキシをオンにすると、テストサイトへはプロキシ経由でつながるので、表示されるアドレスや IPv6 対応はプロキシサーバーのものです。IPv4 しか通さないプロキシだと、IPv6 がないように見えます。自分の回線をテストするには、プロキシをオフにする（またはこれらのホストを直接接続にする）してから再テストしてください。

NAT64 を使う IPv6 専用ネットワークとは？

一部のモバイル回線は、スマートフォンに IPv6 しか割り当てません。それでも IPv4 専用サイトにつながるよう、DNS がそのサイト用の IPv6 アドレスを作り（DNS64）、ゲートウェイが変換します（NAT64）。名前ではサイトが開けますが、IPv4 アドレスを直接入力するとつながりません。テストはそこを見分けます。普通の構成で、ほぼすべてのアプリが動きます。

データは収集されますか？

いいえ。テストはブラウザから各テストホストへ直接行われ、どのサイトとも同じようにホストにはあなたのアドレスが見えます。このサイトは結果を受け取りません。共有リンクにはスコアと各テストの時間だけが入り、アドレスは入りません。コードは GitHub でオープンソースです。

IPv4 と IPv6 の比較は何を示す？

4 つのネットワーク（Cloudflare、Google、Akamai、DNSPod）には、それぞれ IPv4 専用と IPv6 専用の入口があります。テストは両方に同時に接続し、開いた接続で往復時間を測る（3 回の最小値）ので、差はサーバーではなく、プロバイダーが各プロトコルに用意した経路の違いです。結論は両方で応答したネットワークの差の中央値で、10 ms（または 15%）以内なら同じ速さとみなします。

スコアには影響しません。少し遅くても IPv6 は使えます。Google は中国本土では応答せず、DNSPod のサーバーは中国本土にあります。それ以外の地域からは両方とも遅く、その差は中国までの経路の違いです。
