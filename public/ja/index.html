ヘルプ

このテストでは何を調べますか？

回線で IPv6 が使えるか、IPv6 のせいで遅くなっていないかを調べます。ブラウザが普通のサイトを開くのと同じように、小さなテスト用アドレスをいくつか開きます。

IPv4 専用と IPv6 専用のサイト：それぞれにつながるか、どのアドレスでつながったか。

デュアルスタックのサイト（IPv4 と IPv6 の両方のアドレスを持つ）：ブラウザがどちらを選ぶか、IPv6 のタイムアウトを待ってから IPv4 に切り替えていないか。

IPv6 の大きなパケット：新しい接続で、最大サイズのパケットが必要になる大きさのリクエストを送ります。経路の MTU に問題があると、小さな通信は通るのに大きな通信が消え、ページが読み込み中のまま止まります。

ドメイン名のない IP アドレス（IPv6 と IPv4 を一つずつ）：DNS なしで IPv6 につながるか、NAT64 を使う IPv6 専用の回線かどうか。

各テストは 2〜4 社（Cloudflare、Google、DNSPod、AliDNS、icanhazip、ipify）に同時に問い合わせ、最初の応答を使います。1 社がブロックされたり遅かったりしても、テストは失敗しません。

スコアはどう計算していますか？

10 点満点で、回線がどれだけ IPv6 に対応できているかを見る test-ipv6.com の考え方にならっています。IPv6 専用サイトが開ければ 4 点、IPv6 の大きなパケットが通れば 2 点、デュアルスタックのサイトが待たずに開けば 2 点、DNS なしで IPv6 につながれば 1 点、ブラウザが IPv6 を選べば 1 点。IPv6 の最初の応答に 3 秒以上かかると 1 点減点です。

IPv6 がまったくなければ 0 点ですが、回線が壊れているわけではありません。サイトはすべて IPv4 で普通に開けます。10 点は、IPv6 がどこでも使え、何も遅くしていないという意味です。

IPv6 がありません。どうすれば使えますか？

日本の光回線では、IPv6（IPoE）はプロバイダーへの申し込みで使えることが多く、対応ルーターも必要です。ルーターの管理画面で IPv6（IPv6 IPoE、IPv4 over IPv6 など）の設定を確認し、LAN 側で IPv6 アドレスを配る設定（SLAAC や DHCPv6）が有効になっているか見てください。

ルーターに設定がない、またはプロバイダーが対応していない場合は問い合わせてください。スマートフォンのモバイル回線は、Wi-Fi になくても IPv6 があることが多いです。

IPv6 がなくても、困ることはほとんどありません。サイトはすべて IPv4 で開けて、使えないのは IPv6 専用のサイトやアプリだけです。

IPv6 アドレスにはつながるのに、IPv6 専用サイトが開けないのはなぜ？

IPv6 の接続自体は問題ありません。DNS が IPv6 アドレス（AAAA レコード）を返していないため、ブラウザはそのサイトに IPv6 アドレスがあることを知らないのです。よくある原因は、ルーターの AAAA フィルター設定、AAAA レコードを捨ててしまう DNS サーバー、DNS を自前で処理するプロキシアプリです。

対処法：ルーターの AAAA フィルターをオフにするか、1.1.1.1 や 8.8.8.8 などのパブリック DNS に変えてください。

「大きなパケット」のテスト（MTU）とは？

データは最大約 1,500 バイトのパケットに分けて送られます（この上限が MTU です）。一部の IPv6 経路（トンネル、PPPoE、設定ミスのルーター）では、最大サイズのパケットが途中の区間を通れず、「もっと小さくして」という通知もブロックされます。小さな通信は通るので一見つながっているようでも、大きなページや画像、ダウンロードが止まったままになります。

テストは新しい接続で IPv6 専用ホストに 3.5 KB のリクエストを送り、往復とも最大サイズのパケットを使います。小さな IPv6 テストが通るのにこれだけ失敗するなら、ルーターの IPv6 や WAN の設定で MTU を下げる（PPPoE なら 1,480 や 1,452）か、プロバイダーに相談してください。

IPv6 が使えるのに、ブラウザが IPv4 を選ぶのはなぜ？

故障ではなく、IPv6 専用サイトも普通に開けます。ブラウザは両方を同時に試し、先につながったほうを使います（Happy Eyeballs という仕組みです）。IPv4 が勝つのは、その回線で IPv6 の接続に時間がかかるか、システムが IPv4 を優先しているからです。Windows はトンネル経由の IPv6（6to4、Teredo）で IPv4 を優先しますし、IPv4 しか通さないプロキシや VPN アプリも多くあります。

プロキシや VPN を使っています。誰の結果ですか？

ほぼプロキシの結果です。プロキシがオンだと、テスト用サイトへはプロキシ経由でつながるので、表示されるアドレスや IPv6 対応状況はプロキシサーバーのものです。IPv4 しか通さないプロキシだと、IPv6 がないように見えます。自分の回線を調べるには、プロキシをオフにする（またはこれらのホストを直接接続にする）してから、もう一度テストしてください。

NAT64 を使う IPv6 専用の回線とは？

ごく普通の構成で、ほぼすべてのアプリが動くので、何もする必要はありません。一部のモバイル回線は、スマートフォンに IPv6 しか割り当てません。それでも IPv4 専用サイトが開けるように、プロバイダーの DNS がそのサイト用の IPv6 アドレスを作り（DNS64）、ゲートウェイが IPv4 に変換します（NAT64）。ドメイン名ならサイトは開けますが、IPv4 アドレスを直接入力するとつながりません。テストはこの違いで見分けています。

データは収集されますか？

このサイトがテスト結果を受け取ることはありません。テストはブラウザから各テスト用ホスト（Cloudflare、Google など）へ直接行われ、どのサイトを開くときとも同じように、ホスト側には IP アドレスが見えます。結果がリンクに入るのは、あなたが共有したときだけです。リンクに入るのは各テストの結果と時間で、国はチェックを入れたときだけ、IP アドレスは入りません。コードは GitHub で公開しています。

IPv4 と IPv6 の比較では何がわかりますか？

4 つのネットワーク（Cloudflare、Google、Akamai、DNSPod）には、それぞれ IPv4 専用と IPv6 専用の入口があります。テストは両方に同時に接続し、つながった状態で遅延を測ります（3 回のうち最小値）。そのため差はサーバーではなく、プロバイダーが各プロトコルに用意した経路の違いを表します。結論は、両方で応答したネットワークの差の中央値で、10 ms（または 15%）以内なら同じ速さとみなします。

スコアには影響しません。少し遅くても IPv6 は使えます。Google は中国本土では応答しません。DNSPod のサーバーは中国本土にあるため、ほかの地域からはどちらも遅く、その差は中国までの経路の違いを表します。
