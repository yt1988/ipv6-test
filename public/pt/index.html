Ajuda

O que este teste verifica?

Seu navegador abre alguns pequenos endereços de teste, do mesmo jeito que abre qualquer site:

Sites só IPv4 e só IPv6: se você chega a cada internet, e de qual endereço.

Um site de pilha dupla (tem os dois): qual seu navegador escolhe e se ele espera o IPv6 antes de desistir.

Pacotes grandes por IPv6: uma requisição grande o bastante para precisar de pacotes de tamanho máximo, numa conexão nova. Quando a MTU do caminho está quebrada, requisições pequenas funcionam e as grandes somem: páginas que ficam carregando para sempre.

Endereços sem nome, um IPv6 e um IPv4: se o IPv6 funciona sem DNS, e se você está numa rede só IPv6 com NAT64.

Cada teste pergunta a dois ou três provedores ao mesmo tempo (DNSPod, icanhazip, Cloudflare, ipify) e fica com a primeira resposta, então um provedor bloqueado ou lento não o faz falhar.

Como a nota é calculada?

De 0 a 10, seguindo a ideia do test-ipv6.com de medir o quanto uma rede está pronta para IPv6: 4 pontos se sites só IPv6 funcionam, 2 se pacotes grandes passam por IPv6, 2 se sites de pilha dupla abrem sem esperar, 1 se o IPv6 funciona sem DNS, 1 se seu navegador escolhe IPv6. Um ponto a menos se o IPv6 leva mais de 3 segundos para responder. Sem IPv6, a nota é 0, mesmo que todos os sites continuem funcionando por IPv4.

10 significa que o IPv6 funciona em todo lugar e não deixa nada mais lento.

Não tenho IPv6. Como consigo?

A maioria dos provedores já oferece IPv6; muitas vezes está apenas desligado. Na página de administração do roteador, procure IPv6 (ou WAN → IPv6) e escolha o modo do seu provedor, geralmente DHCPv6 ou "nativo", com delegação de prefixo ativada. Depois confira se a rede local distribui endereços IPv6 (SLAAC ou DHCPv6).

Se o roteador não tem opção de IPv6 ou o provedor não oferece, pergunte a eles. No celular, os dados móveis costumam ter IPv6 mesmo quando o Wi-Fi não tem.

Sem IPv6 todos os sites continuam funcionando por IPv4: nada está quebrado, você só fica sem os sites e apps que são só IPv6.

O IPv6 funciona, mas sites só IPv6 falham. Por quê?

A conexão IPv6 está boa, mas seu DNS não devolve endereços IPv6 (registros AAAA), então o navegador nunca fica sabendo que o site tem um. Causas comuns: uma configuração do roteador que filtra registros AAAA, um servidor DNS que os descarta ou um proxy que responde ao DNS por conta própria.

Desligue o filtro AAAA do roteador ou use um DNS público como 1.1.1.1 ou 8.8.8.8.

O que é o teste de pacotes grandes (MTU)?

Os dados viajam em pacotes de até cerca de 1.500 bytes. Em alguns caminhos IPv6 (túneis, PPPoE, roteadores mal configurados) os pacotes cheios não cabem em algum trecho, e a mensagem que pede "mande menores" é bloqueada. Requisições pequenas funcionam, a conexão parece boa, mas páginas grandes, imagens ou downloads travam.

O teste envia uma requisição de 3,5 KB a um host só IPv6 numa conexão nova, o que exige pacotes cheios nos dois sentidos. Se ele falha enquanto o teste IPv6 pequeno passa, diminua a MTU nas configurações IPv6 ou WAN do roteador (tente 1480 ou 1452 com PPPoE) ou fale com seu provedor.

Por que meu navegador escolhe IPv4 se o IPv6 funciona?

Os navegadores tentam os dois e usam o que conecta primeiro (Happy Eyeballs). Se o IPv4 vence, o IPv6 demora mais para conectar na sua rede ou seu sistema prefere IPv4: o Windows faz isso com IPv6 por túnel (6to4, Teredo), e muitos proxies e apps de VPN só levam IPv4. Nada está quebrado; sites só IPv6 continuam abrindo.

Uso proxy ou VPN. De quem é o resultado?

Principalmente do proxy. Com o proxy ligado, os sites de teste são acessados através dele, então os endereços e o suporte a IPv6 mostrados são os do servidor proxy, e um proxy que só leva IPv4 faz parecer que falta IPv6. Para testar sua própria rede, desligue o proxy (ou mande esses hosts direto) e teste de novo.

O que é uma rede só IPv6 com NAT64?

Algumas redes móveis dão aos celulares apenas IPv6. Para ainda alcançar sites só IPv4, o DNS delas inventa um endereço IPv6 para esses sites (DNS64) e um gateway traduz (NAT64). Os sites abrem pelo nome, mas um endereço IPv4 digitado direto não é alcançável, e é isso que o teste percebe. É uma configuração normal e funciona para quase tudo.

Meus dados são coletados?

Não. Os testes vão direto do seu navegador para os hosts de teste, que veem seu endereço como qualquer site. Este site não recebe resultados; um link compartilhado leva só a nota e os tempos, nunca seus endereços. O código é aberto, no GitHub.
